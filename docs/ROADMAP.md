# ROADMAP — 機能バックログ

自動開発ループ（`/evolve`）が参照・更新する機能バックログ。

- ループは **上から順に** `todo` の項目を1つ選んで実装する
- 完了したら `done` に変更し、完了日とコミットハッシュを追記する
- 実装中に問題があり見送った場合は `blocked` にして理由を書く
- 新しいアイデアを思いついたら適切な優先度の位置に `todo` で追加する

## 凡例

- **サイズ**: S（〜1時間相当）/ M（半日相当）/ L（要分割）
- Lの項目はそのまま着手せず、まずS/Mに分割してから実装する

## バグ修正（最優先 — 通常機能より先に上から順に着手する）

ユーザー報告（2026-07-15）。共通の背景: Webviewからの編集はエコーバック抑止
（editor.js の `handleUpdateMessage` が自送信内容をスキップ）により再レンダリング
されないため、**ファイル読み込み時のパーサ（markdownToHtml）で効く記法でも、
入力中はWebview側のライブ変換が無いとGUIに反映されない**。

| 状態 | 内容 | サイズ | 所感（原因の見立てと修正方針） |
|------|------|--------|------|
| todo | タスクリストのライブ入力対応（`- [ ]` / `- []` / `-[]` のいずれを入力してもチェックボックスGUIになる） | M | `- [ ]` はファイル読込時のパーサでしか解釈されない。エディタ内では `- `+スペース時点で通常リストに変換され、続く `[ ]` はテキストのまま残る。修正方針: li先頭の `[]` / `[ ]` / `[x]` をinputイベントで検出しチェックボックスへライブ変換する。`-[]`（スペース無し）はリスト化自体されないため `handleAutoBlock` の拡張も必要 |
| todo | 引用の入力UX改善: `> ` でネスト引用が作れる／Enterで引用から抜ける／Shift+Enterで引用内改行 | M | ネストが効かないのは `handleAutoBlock` が使う `findBlockAncestor` が P/DIV/LI しか返さず、**blockquote内ではnullになり自動変換が発火しない**ため（utils.js）。Enter/Shift+Enterはコードブロック内Enter処理と同様のkeydownハンドラをblockquote用に追加する。`> ` 直後の入力挙動が変なのは、textContent直書きで生成したblockquoteとライブ整形・キャレット処理の干渉が疑われる（実機での再現確認から始める） |
| todo | `**太字**`・`~~取り消し線~~` のライブ変換が実機で効かない（`~~` はツールバーボタンなら機能する） | M | `convertInlineText` は両記法に対応済みで、**jsdomのユニットテストでは変換に成功する**。実機で効かないのは、contenteditableが入力中のテキストを複数のテキストノードに分割し、`walkInline` がノード単位でしか正規表現を当てないため、開始 `**` と終了 `**` が別ノードに割れてマッチしない可能性が高い。修正方針: ブロック要素（P/LI等）単位でテキストを結合してから判定・置換する方式へ変更し、実機相当の分割ノードのテストも追加する |
