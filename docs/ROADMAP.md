# ROADMAP — 機能バックログ

自動開発ループ（`/evolve`）が参照・更新する機能バックログ。

- ループは **上から順に** `todo` の項目を1つ選んで実装する
- 完了したらこのファイルから該当項目を削除し、[docs/roadmap-done.md](./roadmap-done.md) に完了日とコミットハッシュを添えて `done` として追記する
- 実装中に問題があり見送った場合は `blocked` にして理由を書く
- 新しいアイデアを思いついたら適切な優先度の位置に `todo` で追加する

## 凡例

- **サイズ**: S（〜1時間相当）/ M（半日相当）/ L（要分割）
- Lの項目はそのまま着手せず、まずS/Mに分割してから実装する

| todo | 編集中に突然キャレットが先頭へ飛ぶ — 根本対策（ノード基準アンカー化）※応急処置は実装済み | M | **応急処置は完了**（復元失敗時に先頭へ飛ばさず最寄りへフォールバック＝`restoreCursorPosition`, `dc…` サイクル。`(editor,0)` への collapse も先頭飛びとみなしてフォールバックする）。ただしこれは**対症療法**で、下記の**根本原因は未解決**。**根本原因**: キャレット保持がエディタ先頭からの**文字数オフセット**方式（`saveCursorPosition`＝`range.toString().length`／`restoreCursorPosition`＝テキストノードを走査して同数まで数える, [utils.js:83-142](../media/modules/utils.js#L83)）で、**保存時と復元時でキャレット前の文字数が変わると復元に失敗する**（応急処置後は「先頭飛び」ではなく「最寄りへずれる」症状になる＝完全解決ではない）。**文字数がずれる主因**: (1) `contenteditable=false` の埋め込みウィジェット（KaTeX数式・**Mermaid（非同期レンダリング）**・テーブル）の内部テキスト量が保存時と復元時で違う。特に `handleUpdateMessage` は innerHTML 全書き換え後に Mermaid を**非同期**再描画し、キャレット復元を `setTimeout(0)`（[editor.js:629-632](../media/editor.js#L629)）で行うため、復元時点でウィジェットのテキストが未確定になりやすい。(2) 高速入力時に webview→拡張（`edit`, 150msデバウンス）と拡張→webview（`update`, `onDidChangeTextDocument` で毎回全文送信, [markdownEditor.ts:54-66](../src/markdownEditor.ts#L54)）が競合し、`incoming !== current && incoming !== lastSentMarkdown` が成立すると**古い/順序が前後した update で innerHTML 全書き換え**が起きる。**修正方針**: オフセット方式をやめ、キャレットのアンカーをノード基準（保存対象ブロックのID＋ブロック内オフセット、または `Range` のコンテナ参照）で保持する。Mermaid等の非同期描画完了後に復元する、`handleUpdateMessage` の全書き換えを差分適用へ変える、古い `update` を無視する（バージョン番号付与）等も併せて検討 |
| todo | ブロック数式を右クリックでコピーした画像が崩れる（レイアウト・上付き/下付きが壊れる） | M | 再現手順: `$$ \int_{-\infty}^{\infty} e^{-x^2} dx = \sqrt{\pi} $$` をブロック数式としてレンダリングし、右クリック→画像コピーで保存すると、√記号が式の左上に飛ぶ・上付き/下付き（`-\infty`〜`\infty`、`e^{-x^2}`）がベースラインに落ちて `e-x2` のように潰れる（添付図参照）。原因候補: 画像化（html2canvas 等）が KaTeX/MathJax の描画に使うフォント／CSS（上付き下付きの `vertical-align`・`position`、`sqrt` の overline SVG や擬似要素）を取り込めていない。Mermaid の PNG 化で確立した「クリーンHTML抽出→変換」の流れを流用しつつ、数式用フォントとKaTeX CSSをキャプチャ対象に含める必要がある。まず実機で再現確認し、どのライブラリで描画・キャプチャしているか特定してから着手 |
| todo | マウスドラッグでの本文選択が装飾記号（`**`等）に到達すると解除される | M | 再現手順: マウスドラッグで本文を範囲選択していくと、`**`（太字）などの装飾マーカー部分にカーソルが差しかかった瞬間に選択が解除されてしまい、装飾をまたいだテキストを選択してコピペできない。期待動作: 装飾記号をまたいでも選択が連続して維持される。原因候補: WYSIWYG表示で装飾マーカーの表示/非表示を切り替える処理（`selectionchange`／`mouseover` 等でのDOM再構築）がドラッグ中の Selection を破棄している。ドラッグ選択中はマーカーのトグルを抑止する、または選択範囲を保存・復元する必要がある。まず実機で再現確認 |
| todo | 行番号がすべての行に表示されない（行番号ガターの欠落）※優先度低め | S | Raw モードの行番号ガター（`fcf630e` で実装）で、一部の行に行番号が表示されない。全論理行に対して番号が振られるべき。原因候補: ガターの行番号生成が textarea の実際の行数とずれている（末尾行・空行の扱い、あるいはミラー測定の高さずれ）。ユーザー申告により**優先度は低め**でよい。まず実機で再現確認 |

| todo | Mermaid図の画像コピー／保存時に背景色を選べるようにする（透過・白・黒） | M | ユーザー要望。現状 Mermaid図のPNG化は背景が **白で固定**（`mermaid.js` の `svgToPngBlob` が `ctx = getContext('2d', { alpha: false })` で不透明キャンバスを作り `ctx.fillStyle = '#ffffff'`／`fillRect` で白背景を塗っている, [mermaid.js:442-457](../media/modules/mermaid.js#L442)）。「画像をコピー」（`copyToClipboard`→`svgToPngBlob`）と「PNG画像として保存」（`saveAsPng`→`svgToPngBlob`）の**両方**で背景色を **透過／白／黒** から選べるようにする。**実装方針**: (1) `svgToPngBlob(svgElement, scale, background)` に背景引数を追加。`'transparent'` のときは `getContext('2d', { alpha: true })`（不透明化を外す）で `fillRect` を行わず透過PNGにし、`'white'`/`'black'` のときは従来どおり不透明キャンバスに該当色を塗る。html2canvas 経由の中間ラスタライズ（`backgroundColor: '#ffffff'`, [mermaid.js:421](../media/modules/mermaid.js#L421)）も透過時は `null`／`'transparent'` にする必要がある点に注意（ここで白が焼き込まれると最終段で透過にできない）。(2) 呼び出し側 `copyToClipboard`/`saveAsPng` に背景色を渡す。(3) UIは Mermaid右クリックメニュー（`src/markdownEditor.ts` の `#mermaidContextMenu`＝`data-action="copyImage"`／`"savePng"` の2項目, [markdownEditor.ts:236-238](../src/markdownEditor.ts#L236)）を拡張する。各アクションを背景色つきに増やす（例: 「画像をコピー（白／黒／透過）」のサブメニューまたは3項目）か、メニューに背景色トグルを設けて選択状態を `svgToPngBlob` へ渡す。メニュー項目のクリック配線は `mermaid.js` の `setupContextMenuEvents`（`data-action` 分岐, [mermaid.js:586-600](../media/modules/mermaid.js#L586)）。**注意**: 数式（`math.js` の `blockToPngBlob`）も同様に白背景固定だが本項目のスコープ外（必要なら別途 todo 化）。PNGの見た目・クリップボード/保存はレイアウト・OS依存のため**実機（拡張機能開発ホスト）確認が前提**。ユニットテストは背景引数の分岐（透過時に `fillRect` を呼ばない・`alpha` 設定が切り替わる）を純粋に検証できる範囲で追加 |
